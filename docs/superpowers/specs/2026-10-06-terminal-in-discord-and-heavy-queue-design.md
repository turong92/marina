## 1. 터미널 넘기기를 Discord 플러그인으로

### 지금
세션이 `ask_terminal` → runtime 의 `marina term-request` 가 토큰을 쓰고 `{대시보드}/term-run?t=…` 링크를 만든다 → 링크를 열면 대시보드 프로세스 안의 웹 터미널(pty)이 뜬다. 대시보드를 내리면 버튼은 생기는데 안 열린다.

### 바꿀 모양
- **터미널 = tmux 세션.** 요청마다 `term-<id>` tmux 세션을 그 작업의 워크트리에서 띄우고 명령을 입력창에 미리 쳐 둔다(Enter 는 사람이).
  - 왜 pty 가 아니라 tmux 인가: Discord 데몬은 배포할 때마다 스스로 다시 뜬다. 데몬이 쥔 pty 는 그때 죽는다(대시보드가 "터미널이 살아 있으면 재시작 안 함" 관문을 뒀던 이유). tmux 는 데몬과 무관하게 산다.
  - 덤: 형이 맥 앞이면 `tmux attach` 로도 붙을 수 있고, 세션이 화면을 읽어 "끝났다"를 스스로 알 수 있다.
- **화면 = Discord 데몬의 자체 서버(3905, 결과물 열어보기와 같은 서버).** `/t/<토큰>/` 페이지가 0.5초마다 화면(`tmux capture-pane`)을 받아 그리고, 입력은 `send-keys` 로 보낸다. 글자 입력칸 + Enter·Ctrl-C·Tab·방향키·Esc 버튼. 웹소켓·xterm.js 없음.
  - 한계: 색·커서 이동이 많은 화면(vim 등)은 거칠다. 대상은 로그인·승인류 명령(`gcloud auth login`, `gh auth login`)이라 충분하다.
- **누가 열 수 있나 = 그 채널을 보는 사람(형 결정).** 지금처럼 채널에 링크를 올린다. 개발 채널은 형이 들인 사람만 보므로 버튼을 한 번 더 거치게 하지 않는다.
  - 링크는 한 번만 열 수 있고(먼저 연 브라우저에 쿠키로 묶는다) 10분 안에 안 열면 죽는다. 링크가 채널 밖으로 새거나 나중에 다시 눌려도 셸이 열리지 않게 하는 최소 장치다.
- **끝:** 명령이 끝나면(셸 프롬프트로 돌아옴) 페이지에 "끝났어" + 세션에 알림. tmux 세션은 30분 뒤 정리.
- 채팅방(chat) 세션에는 제공하지 않는다(지금과 같다).

### 손댈 곳 (전부 plugin-discord/)
- `marina_termbridge.py`(새): tmux 세션 만들기·화면 읽기·키 보내기·정리, 토큰 기록(`~/.marina/discord-term/`).
- `marina_view.py` 의 서버에 `/t/` 경로 추가, `marina-view/term.html·js`.
- `marina_session.py` `ask_terminal`: runtime CLI 호출을 걷어내고 위 모듈로.
- runtime 쪽 `/term-run`·`marina term-request` 는 이번엔 그대로 둔다(대시보드를 쓰는 팀원용). Discord 는 더 이상 안 부른다.

### 검증
- 단위: 토큰 일회용·만료·쿠키 묶기, 화면 읽기·키 보내기(가짜 tmux), 데몬이 다시 떠도 tmux 세션과 토큰이 이어지는지.
- 실측: 폰에서 버튼 → 링크 → 명령 Enter → 결과, 데몬 재시작 뒤 같은 페이지가 이어지는지.

## 2·3. 무거운 명령 줄 세우기 (부하 기다리기 + 마구잡이 테스트 줄이기)

### 원인
- 세션은 서로를 모른다. 각자 "지금 테스트 돌려야지" 하고 돌린다.
- 서브에이전트마다 작업 끝에 전체 스위트를 돌린다(TDD 스킬의 "프로젝트 스위트를 돌려라" + 구현자·리뷰어가 각각). 병렬 에이전트 4개면 전체 스위트 4개가 동시에 돈다.
- 같은 코드에서 같은 테스트를 몇 분 간격으로 다시 돌린다(구현자가 돌리고, 리뷰어가 또, 지휘 세션이 또).
- 규칙 문구로는 못 막는다 — 지키는 주체가 20개 세션 × 서브에이전트라서.

### 장치: `heavy` — 맥 전체에 하나뿐인 줄
무거운 명령(빌드·테스트)을 맥 전체에서 동시에 N개만 돌게 한다. 에이전트가 따로 부를 필요 없이 **훅이 알아서 끼운다.**

- **끼우기:** PreToolUse(Bash) 훅이 명령이 무거운 종류면(`gradlew`, `vitest`, `pnpm|npm … test|build`, `pytest`, `run-affected.sh`, `cargo test`, `go test`, `tsc`, `docker build` …) 명령을 `heavy -- <원래 명령>` 으로 바꿔 넘긴다. 에이전트가 본 명령·출력은 그대로다.
- **줄:** `heavy` 는 자리(기본 3개)를 잡을 때까지 기다린다. 기다리는 동안 "앞에 2개, 3분째 대기 — homeserver 의 gradle test 가 도는 중" 을 찍는다.
- **너비 제한:** 자리를 잡은 명령에는 도구별 병렬 수를 낮춰 준다(gradle `--max-workers=4`, vitest `--maxWorkers=4` 를 환경변수·인자로). 자리 3 × 일꾼 4 = 코어 12.
- **부하 보기:** 자리가 비어도 메모리 압박이 '위험'이거나 스왑이 급히 늘면 새로 들이지 않는다. 줄 밖의 일(도커, 형이 직접 돌리는 것) 때문에 바쁜 경우까지 본다.
- **기다림과 도구 제한 시간:** Bash 도구는 기본 2분에 끊는다. 60초 안에 자리가 안 나면 `heavy` 가 바로 끝나며 "줄이 길다 — 같은 명령을 백그라운드 실행(run_in_background)으로 다시 걸어라" 를 돌려준다. 백그라운드 실행은 오래 기다려도 된다.
- **같은 결과 다시 쓰기:** 같은 폴더·같은 명령·같은 코드 상태(git HEAD + 안 올린 변경의 해시)로 10분 안에 **통과한** 기록이 있으면 다시 돌리지 않고 그 출력을 돌려준다("4분 전 같은 코드에서 통과 — 다시 안 돌림. 새로 돌리려면 HEAVY_FRESH=1"). 실패한 결과는 다시 쓰지 않는다(다시 돌려 봐야 하므로).
- **보이기:** Discord #상태 아랫줄에 `🧪 실행 3 · 대기 5`. 누가 도는지·기다리는지는 `heavy status`.
- **빠져나가기:** `HEAVY_OFF=1` 이면 그냥 실행. 훅·줄이 고장 나면 막지 않고 그대로 실행한다(fail-open).

### 어디에 두나
- 맥 전체·모든 프로젝트에 걸치는 장치라 marina 가 아니라 `~/IdeaProjects/sumin/shared/bin/heavy` + 전역 `~/.claude/settings.json` 훅(role-hook·cloud 래퍼와 같은 자리).
- Discord 세션뿐 아니라 형이 직접 여는 세션·서브에이전트에도 걸린다. Codex 세션에는 안 걸린다(훅 체계가 다르다 — 필요하면 따로).

### 같이 고칠 규칙 (장치를 보완)
- 역할 정본 `developer`: "작업 중에는 바뀐 범위의 테스트만(파일·클래스 지정). 전체 스위트는 지휘 세션이 시킬 때만."
- `/team`·전역 규칙: "병렬로 돌린 developer 들의 결과는 지휘 세션이 모아 전체 스위트를 한 번 돌린다. 리뷰어는 테스트를 다시 돌리지 않고 구현자가 남긴 결과를 본다."
- TDD 스킬의 "프로젝트 스위트를 돌려라"와 부딪히는 부분은 전역 규칙이 우선한다고 적는다(역할 우선 규칙과 같은 방식).

### 검증
- 단위: 무거운 명령 판정(오탐 — `echo gradlew`, `grep vitest` — 은 안 끼움), 자리 3개일 때 4번째가 기다리는지, 60초 넘으면 안내와 함께 끝나는지, 통과 결과만 다시 쓰는지, 코드가 바뀌면 다시 돌리는지, 훅이 죽어도 원래 명령이 도는지.
- 실측: 세션 3~4개에서 동시에 테스트를 걸어 #상태의 "밀림" 배수와 총 소요 시간을 장치 전후로 비교.
