## 1. 목적 · 범위 · 비목표

**목적.** 형이 맥을 재부팅하든 방이 꺼져 있든, **Discord 에 글을 쓰면 답이 온다.** 그리고 오래 쉰 방은 알아서 내려 메모리를 돌려받는다 — 깨울 때 토큰을 더 쓰지 않는 조건에서만.

**범위 (세 동작).**
1. 봇 데몬 재기동 보장 — 로그인하면 뜨고, 죽으면 다시 뜬다(LaunchAgent `marina.discord`).
2. 꺼진 방 깨우기 — 꺼진 방(개발·채팅·로비)에 허용된 사람이 글을 쓰면 봇이 그 방 세션을 띄우고 그 글을 첫 지시로 넘긴다.
3. 쉰 방 내리기 — 기준 시간 넘게 쉬었고 잃을 일이 없는 방의 세션을 내린다.

**비목표.**
- 죽은 백그라운드 셸·서브에이전트·예약 깨우기(ScheduleWakeup)를 되살리는 것. 재부팅으로 죽은 것은 못 살린다. 그래서 ③은 그런 게 없을 때만 내린다.
- 버튼·슬래시 명령·🛑 반응으로 깨우기. 글만 깨운다.
- 메시지 수정·삭제에 반응하기.
- 리눅스(systemd) 등록. 맥 기본 홈이 아니면 지금 방식(훅이 띄움) 그대로다.
- runtime·대시보드 쪽 변경, 대시보드가 봇을 띄우게 되돌리기(분리 B 원칙: Discord 는 혼자 돈다).
- 깨우기 대기열·우선순위. 방마다 독립으로 깨운다.

## 2. 토큰 근거 (지휘 세션 판단 + 이 문서의 조건)

전제:
- `claude --resume` 자체는 API 를 부르지 않는다. 다음 글이 올 때 전체 컨텍스트를 읽는다.
- 프롬프트 캐시는 최장 1시간. 1시간 넘게 쉰 방은 **켜 둬도** 다음 글에서 캐시 없이 전체를 다시 읽는다. 그러니 그런 방은 내렸다 깨워도 읽는 양이 같다.

이 설계가 지키는 조건:

| 조건 | 어떻게 |
|---|---|
| A. 캐시가 살아 있는 방은 안 내린다 | 기준 시간은 2시간 미만으로 못 내린다(설정이 더 작으면 2시간으로 올린다). 기본값은 §형 결정 |
| B. 깨우기 자체는 토큰 0 | 봇·REST·tmux 만 쓴다. Claude 가 도는 것은 형의 그 글이 원래 만들었을 턴 하나뿐이다 |
| C. 깨우기가 턴을 더 만들지 않는다 | 밀린 글은 첫 지시 **하나**에 모아 넘긴다. 기존 이어받기 문구(`RESUME_TEXT`)와 겹치면 깨우기 쪽 하나만 친다. "깨어나는 동안 온 글" 보충 입력은 실제로 놓친 글이 있을 때만 한다 |
| D. 내리면서 잃는 것이 없다 | `restart_blockers` 가 빈 상태가 60초 이어질 때만 내린다(§5) |

손해가 생길 수 있는 곳(숨기지 않는다):
- 다시 띄운 세션이 전에 읽은 파일을 고치려면 다시 읽어야 할 수 있다(미확인, §10).
- 깨어나는 몇 초 사이에 글이 더 오면 보충 입력 한 턴이 든다(§4.5).
- 밀린 글이 8KB 를 넘으면 본문 대신 "fetch_messages 로 읽어"를 넘겨 도구 호출이 한 번 든다(§4.4).

재부팅으로 죽은 방을 1시간 안에 깨우는 경우는 캐시가 살아 있을 수도 있지만, 이건 내림이 만든 상황이 아니다(재부팅이 만들었다). 유휴 내림은 조건 A 때문에 이 경우를 만들지 않는다.

## 3. 동작 ① 봇 데몬 재기동 보장

### 3.1 무엇을 등록하나
- 파일: `~/Library/LaunchAgents/marina.discord.plist`, 라벨 `marina.discord`.
- 실행: 고정 입구 `~/.marina/bin/marina-session-hook daemon`. 입구가 부를 때마다 설치 목록에서 최신 설치본을 찾으므로 plist 는 업데이트 때 안 바뀐다.
- `RunAtLoad`·`KeepAlive` = true → 로그인하면 뜨고, 어떤 이유로 끝나도 launchd 가 다시 띄운다(재시도 간격은 launchd 기본 10초).
- `AbandonProcessGroup` = true → 데몬이 끝날 때 launchd 가 그 자식들(진행 중인 새 작업 열기·깨우기)을 같이 죽이지 않는다. 지금(훅이 떼어 띄운 데몬)과 같은 동작을 지킨다. bun 봇은 부모가 죽으면 10초 안에 스스로 끝난다(기존 `MARINA_PARENT_PID` 감시).
- `WorkingDirectory` = `~/.marina`(워크트리를 cwd 로 물지 않는다 — 기존 리뷰 I2), 로그 = `~/.marina/discord-daemon.log`(지금과 같은 파일. 데몬이 뜰 때 1MB 를 넘으면 비운다).
- 환경: `PATH` = `daemon_path()`(~/.local/bin·homebrew·시스템), `MARINA_HOME`, `PYTHONUNBUFFERED=1`, `LANG=en_US.UTF-8`, `MARINA_DISCORD_SUPERVISED=launchd`.
  - `LANG` 을 박는 이유: launchd 는 `LANG` 을 안 준다. UTF-8 이 아니면 tmux 화면 판정(`❯`·`⏺ main`·한글)이 깨질 수 있다. 값이 고정이라 plist 내용이 누가 써도 같다.
- **"재부팅 뒤"는 정확히는 "로그인 뒤"다.** LaunchAgent 는 사용자 로그인 때 올라온다.

### 3.2 누가 주인인가 — 한 홈에 한 주인
| 환경 | 데몬을 띄우는 주인 |
|---|---|
| 맥 + 기본 홈(`~/.marina`) + `launchctl` 있음 | **launchd 만.** 훅·명령의 `ensure_daemon()` 은 떼어 띄우지 않고 launchd 에 맡긴다(없으면 등록, 등록돼 있는데 죽어 있으면 `kickstart`) |
| 그 밖(격리 홈·테스트·리눅스) | 지금 그대로 — pid 파일 + spawn 잠금으로 떼어 띄운다 |

- **등록은 실행 인자가 고정 입구(`~/.marina/bin/marina-session-hook`)일 때만 한다.** 작업 트리에서 직접 돌린 데몬(설치본이 아님)은 등록하지 않고 지금 방식으로 돈다 — LaunchAgent 가 워크트리 파일을 가리키면 그 워크트리를 지우는 순간 봇이 죽는다.
- 테스트·프리뷰 홈은 절대 실제 launchd 를 건드리지 않는다. 기본 홈이 아니면 실제 `launchctl` 을 부르지 않는다(테스트는 가짜 `launchctl` 을 `MARINA_DISCORD_LAUNCHCTL` 로 넣고, plist 위치도 `MARINA_LAUNCH_AGENTS_DIR` 로 임시 폴더를 쓴다).
- `MARINA_DISCORD_DAEMON=off` 면 지금처럼 `ensure_daemon()` 이 맨 먼저 `off` 로 돌아간다. 등록·kickstart·plist 쓰기를 하나도 하지 않는다.

### 3.3 설치·갱신·제거 시점
| 시점 | 주체 | 하는 일 |
|---|---|---|
| 훅(`hook_stop`·`hook_prompt`)·명령(`new/start/restart/lobby`) | `ensure_daemon()` | 데몬이 살아 있으면 지금처럼 바로 끝(pid 파일 확인 — 훅 지연 그대로). **죽어 있을 때만** plist 를 확인해 없거나 다르면 쓰고, 등록 안 돼 있으면 `bootstrap`, 돼 있으면 `kickstart` |
| 떼어 띄운 데몬이 새 코드로 뜰 때(첫 배포) | 데몬 자신 | 자기가 launchd 자식이 아니고 위 표의 맥 환경이면 등록하고 **자기는 루프를 돌지 않고 끝난다.** launchd 가 띄운 데몬이 이어받는다 |
| `marina-session daemon-ensure` | 형·배포 절차 | 위와 같은 확인을 손으로 |
| plist 내용이 코드가 만드는 것과 다를 때 | 발견한 쪽 | 파일을 새로 쓰고, **떼어 낸 도우미**가 `bootout` → `bootstrap` 한다(데몬 자신이 발견해도 자기를 내리다 중간에 죽지 않게) |
| `marina-session daemon-uninstall` | 형 | `bootout` + plist 삭제. 플러그인을 지우기 전에 부른다 |

팀원 맥: 플러그인이 깔려 있고 `~/.marina/discord.json` 이 있으면 첫 훅·자동 업데이트 뒤 데몬 교체 때 위 경로로 저절로 등록된다. 손으로 할 일이 없다. `discord.json` 이 없으면 훅이 `ensure_daemon()` 을 부르지 않으므로(지금과 같다) 등록도 안 된다.

### 3.4 업데이트 핸드오프와 KeepAlive 가 부딪치지 않게
지금: 데몬이 1분마다 새 설치본을 확인 → 있으면 루프를 끝내고 `_daemon_handoff()` 가 새 코드 데몬을 **직접 떼어 띄운다.**
이걸 launchd 아래에서 그대로 하면 "직접 띄운 것 + launchd 가 다시 띄운 것" 둘이 된다.

- launchd 가 띄운 데몬(`MARINA_DISCORD_SUPERVISED=launchd`)은 핸드오프에서 **아무것도 띄우지 않고 끝나기만 한다.** launchd 가 다시 띄우고, 입구가 최신 설치본을 고른다. 공백은 launchd 재시도 간격(약 10초)이다.
- 그 공백에 훅이 `ensure_daemon()` 을 불러도 주인이 launchd 하나라 둘이 뜨지 않는다(`kickstart` 는 이미 떠 있으면 아무것도 안 한다).
- 안전망은 그대로 둔다: `Loop.own()` 의 `discord-bot.lock` — 같은 홈에서 봇·#상태를 돌리는 것은 잠금을 쥔 하나뿐이다. 잠금을 못 쥔 쪽은 끝나지 않고 30초마다 다시 본다(끝나면 launchd 가 10초마다 다시 띄워 로그만 쌓인다).
- 첫 배포 순서(자동): 옛 데몬이 새 설치본을 보고 핸드오프 → 새 코드 데몬이 떼어 뜬다 → 그 데몬이 §3.3 대로 등록하고 끝난다 → launchd 데몬이 맡는다. 옛 데몬이 아직 잠금을 쥐고 있으면 launchd 데몬은 기다렸다 이어받는다.

## 4. 동작 ② 꺼진 방 깨우기

### 4.1 감지 — 봇이 글 이벤트를 받는다
- `bot.ts` 에 Gateway 인텐트 `GuildMessages` 를 더하고 `MessageCreate` 를 받는다. 이 인텐트는 특권 인텐트가 아니라 포털 설정이 필요 없다.
- **`MessageContent` 인텐트는 선언하지 않는다.** 봇은 글 내용을 읽지 않고 채널·글쓴이·메시지 ID 만 파이썬에 넘긴다(`marina_discord_wake.py wake --channel … --user … --message … --thread …`). 내용이 필요한 순간(§4.4)에는 파이썬이 REST 로 읽는다.
- 봇이 쓴 글(`author.bot`)과 다른 서버 글은 `bot.ts` 에서 바로 버린다. 판단은 전부 파이썬이 한다(기존 원칙).
- 스레드에 쓴 글은 부모 채널의 방으로 본다(공식 플러그인·🛑 처리와 같은 규칙).

### 4.2 누구 글에 반응하나
공식 플러그인이 받는 글과 **같은 규칙**으로 고른다. 켜져 있었다면 세션이 받았을 글만 깨운다.
- 그 방 상태 폴더 `access.json` 의 `groups.<채널>.allowFrom` 에 있는 사람. 목록이 비어 있으면(채팅방) 그 채널에 글을 쓸 수 있는 사람 모두.
- 봇·웹훅 글 제외. 일반 글·답글만(시스템 메시지 제외). 본문도 첨부도 없는 글 제외.
- `requireMention` 이 true 인 방은 깨우지 않는다(마리나가 만든 방은 전부 false).
- 허용 안 된 사람의 글은 조용히 무시한다(반응·안내 없음). 밀린 글을 모을 때도 허용된 사람 글만 넣는다.

### 4.3 깨우는 순서
1. 방 찾기(채널 → `sessions.json`). 모르는 채널이면 끝.
2. tmux 가 살아 있으면 끝 — 그 세션의 플러그인이 직접 받는다.
3. **방마다 잠금**(`<상태 폴더>/wake.lock`, 기다리지 않음). 못 쥐면 끝 — 이미 누가 깨우는 중이다. 쥔 뒤 tmux 를 한 번 더 본다.
4. 밀린 글 모으기(§4.4). 하나도 없으면 끝.
5. 표시: 가장 최근 글에 ⏰ 반응 + 채널에 '입력 중…' 한 번.
6. 띄우기: 기존 `cmd_start` 에 첫 지시를 얹는다(`claude --resume … "<첫 지시>"`). 설정 다시 쓰기·워크트리 잠금·기록 찾기는 `cmd_start` 가 지금 하는 그대로다.
7. 성공: ⏰ 를 뗀다(곧 세션 훅이 👀·🛑 을 단다). `woke.json` 에 시각과 넘긴 글 ID 를 적고 §4.5 확인을 떼어 예약한다.
8. 실패: ⏰ → ⚠️, 채널에 이유 한 줄("⚠ 못 깨웠어 — …"). 같은 방 안내는 10분에 한 번만(글마다 반복하지 않는다).

**동시에 여러 글이 와도 한 번만:** 3의 잠금 + 6에서 띄운 뒤엔 2에서 걸러진다. `restart` 대기자나 형이 같은 순간에 `start` 해서 tmux 이름이 겹치면, 진 쪽은 "이미 떠 있음"으로 보고 실패 안내를 하지 않는다.

### 4.4 무엇을 넘기나 — 밀린 글을 첫 지시 하나로
- 기준 = 그 세션이 **마지막으로 읽은** 이 채널 글(세션 기록의 `<channel …>` 태그, 기존 `inbound_messages`). REST 로 그 뒤 글을 읽어(`GET /channels/<id>/messages?after=…`) §4.2 규칙으로 거르고, 기록에 이미 있는 것(대기열에만 들어온 것 포함)은 뺀다.
- 그중 **이번 글과 그 앞 10분 안의 글**을 본문째 넘긴다. 형이 연달아 쓴 글이 한 턴에 들어간다.
- 그보다 오래된 못 읽은 글은 본문을 넣지 않고 개수만 알린다 — "그 전에도 못 읽은 글이 N개 있어. 필요하면 fetch_messages 로 보되, 지난 지시를 묻지 않고 실행하지는 마." 사흘 전에 쓴 "배포해"가 오늘 "상태 어때?"에 딸려 실행되면 안 된다.
- 기준을 못 찾으면(기록 끝 2MB 에 이 채널 글이 없음) 이번 글 하나만 넘긴다.
- 스레드에 쓴 글은 그 글 하나만(`chat_id` = 스레드 ID, 플러그인과 같다).
- 형식: 새 작업 버튼과 같은 `<channel source="plugin:discord:discord" chat_id message_id user ts>` 태그(첨부는 `attachment_count`·`attachments` 속성 — 세션이 `download_attachment` 로 받는다) + 끝에 안내 한 줄. 이 태그라서 받은 순간 👀, 도구별 이모지, 🛑, `reply_to` 자동 채움, 턴 끝 정리가 켜져 있던 방과 똑같이 돈다.
- 크기: 첫 지시는 8000바이트까지. 넘치면 오래된 글부터 본문을 빼고, 그래도 넘치면 본문 없이 "메시지 N개가 왔어(마지막 ID …). fetch_messages 로 읽고 답해"만 넘긴다. tmux 가 한 명령으로 받는 길이에 한도가 있어서다(§10 실측).
- 본문의 `</channel` 은 깨뜨려 넣고, 글쓴이 이름은 기존 규칙으로 거른다(태그 탈출 방지 — 기존 `new_task_first_prompt` 와 같은 처리).
- 재시작 전에 받고 답 못 한 글이 기록에 남아 있으면(기존 `unanswered`) 안내 줄에 "그것도 이어서 답해"를 붙이고, `RESUME_TEXT` 는 따로 치지 않는다(턴 하나로).

### 4.5 깨어나는 동안 온 글
첫 지시는 세션을 띄우기 직전에 모은다. 그 뒤부터 그 세션의 플러그인이 Discord 에 접속할 때까지(몇 초~십몇 초) 온 글은 누구도 못 받는다. 형은 글을 연달아 쓰므로 흔한 경우다.
- 깨운 지 45초 뒤, 떼어 낸 확인 프로세스가 한 번 본다: 깨운 뒤에 온 허용된 글 중 **15초 넘게 지났는데 세션 기록에 흔적이 없는 것**이 있나.
- 있으면 고정 문구 하나를 세션 입력창에 친다(기존 `type` 경로 — 세션이 쉬고 입력창이 비었을 때만): "깨어나는 동안 이 채널에 메시지가 더 왔는데 받지 못했어. fetch_messages 로 최근 메시지를 읽고, 아직 답하지 않은 것에 답해 줘."
- 없으면 아무것도 안 한다(토큰 0). 사용자 글 본문을 입력창에 치지는 않는다(기존 `typeable` 허용 목록에 이 문구만 더한다).

### 4.6 봇이 꺼져 있던 동안 온 글
봇이 없던 시간(재부팅·업데이트 교체 10초·크래시)에 온 글은 이벤트로 안 온다.
- 데몬은 1분마다 `~/.marina/discord-daemon.beat` 를 찍는다. 뜰 때 이전 값을 읽어 "그때부터 지금까지" 온 글을 꺼진 방마다 한 번 훑는다(§4.4 와 같은 모으기, 방 하나씩 차례로).
- 12시간보다 오래된 글은 스스로 실행하지 않는다(밤새 꺼 둔 맥은 되고, 일주일 꺼 둔 맥은 안 된다). 10분 안에 깨운 적 있는 방은 건너뛴다.
- beat 가 없으면(첫 배포) 훑지 않는다 — 배포 전에 쌓인 옛 글로 방들이 한꺼번에 깨어나지 않게.

### 4.7 경계 조건
| 경우 | 동작 |
|---|---|
| 워크트리가 없는 개발 방 | 못 깨운다. ⚠️ + "워크트리가 없어" 한 줄. 이런 방은 기존 `reconcile_gone` 이 2분쯤 뒤 채널째 정리한다 |
| 채팅방·로비 | 같은 규칙으로 깨운다(폴더는 항상 있다). 로비를 항상 켜 둘지는 §형 결정 |
| 대화 기록이 없는 방 | 채팅·로비는 기존대로 같은 ID 로 새로 시작한다. 개발 방은 `--continue` 가 실패하면 실패 안내 |
| claude 가 뜨자마자 죽음 | 실패 안내(이유 포함). 기존 "세션이 꺼졌어" 알림도 같이 온다 |
| 형이 `stop` 으로 끈 방 | 깨운다(§형 결정) |
| 로비의 [🛠 새 작업 열기] 버튼 | 세션 없이 봇만으로 동작한다(기존). 재부팅 뒤 봇만 뜨면 바로 쓸 수 있다 |
| Discord REST 실패 | 깨우지 않고 로그만. 다음 글이 다시 시도한다 |
| 깨운 세션의 환경 | 세션을 띄울 때 쓴 `PATH`·`LANG`·`LC_ALL` 을 `<상태 폴더>/launch-env.json` 에 적어 두고, 깨울 때 그 값으로 띄운다. 없으면 `daemon_path()`. 봇(launchd)의 짧은 PATH 로 띄우면 형이 손으로 켠 세션과 node·MCP 서버가 달라진다 |
| `"wake": false` (discord.json) | 깨우기를 끈다. 이때는 ③도 같이 꺼진다(내리기만 하고 못 깨우면 손해) |

## 5. 동작 ③ 쉰 방 내리기

### 5.1 마지막 활동을 무엇으로 재나
세션 기록 파일의 수정 시각은 **쓰지 않는다**(재기동·종료로 바뀐다는 실측이 있다). 훅이 직접 적는 시각만 쓴다.

마지막 활동 = 다음 중 가장 늦은 것:
- `turn-at`(지시를 받은 순간 — Discord·터미널·원격 조종 모두)
- `stopped-at`(턴 끝·정지)
- `activity-at` 수정 시각(도구 사용)
- tmux 세션이 만들어진 시각(방금 켠 세션을 바로 내리지 않게)

### 5.2 내리는 조건 — 전부 만족해야 한다
1. 설정이 켜져 있다(`idleStopHours` > 0, 깨우기 켜짐). bun 봇이 떠 있다(봇이 죽어 있으면 깨울 수 없으니 내리지도 않는다).
2. tmux 가 살아 있고 대화 기록이 있다(기록이 없는 세션은 다시 못 이을 수 있어 안 내린다).
3. 마지막 활동이 기준 시간보다 오래됐다.
4. 그 tmux 세션에 붙어 있는 터미널이 없다(형이 `attach` 로 보는 중이 아니다).
5. 입력창이 비어 있다 — 쓰다 만 글, 계획 승인·선택 창이 떠 있으면 안 내린다(기존 `_input_empty`).
6. `restart_blockers(rec)` 가 비어 있다. 이 상태가 **60초 이어져야** 하고(중간에 한 번이라도 막히면 처음부터), 죽이기 직전에 한 번 더 본다 — 안전 재시작과 같은 규칙이다.
7. 안전 재시작 대기(`restart …`)가 돌고 있지 않다(대기자가 "꺼진 세션은 그냥 시작"하므로 서로 껐다 켰다 하게 된다).

보수적으로:
- 판정 중 예외가 나면 내리지 않는다(`restart_blockers` 가 이미 그렇게 한다. 새 조건도 같다).
- 한 바퀴(1분)에 **하나만** 내린다. 잘못 판정해도 한꺼번에 죽지 않고 #상태에서 보인다.
- 막힌 방은 10분 뒤에 다시 본다(매분 2MB 기록을 다시 읽지 않는다).
- 내릴 때마다 `discord-bot.log` 에 방·쉰 시간을 남긴다.
- 읽기만 하는 명령 `marina-session idle-check [--hours N]` 으로 방마다 "내릴 대상인가 · 아니라면 왜"를 미리 볼 수 있다. 죽이는 명령은 만들지 않는다.

### 5.3 내린 뒤
- `tmux kill-session` 뿐이다. 채널·상태 폴더·워크트리·git 잠금은 그대로다(형이 `stop` 한 것과 같다 — runtime 의 워크트리 7일 정리는 잠금 때문에 계속 건너뛴다). "세션이 꺼졌어" 알림은 안 간다(kill 은 원래 알리지 않는다).
- 내린 직후 그 방을 한 번 확인한다: 방금 사이에 온 못 읽은 글이 있으면 바로 다시 깨운다(내리는 순간과 글 도착이 겹친 경우).
- 채널에 "내렸어"를 남길지는 §형 결정.

## 6. #상태 표시

지금 "⚫ 꺼짐"은 "꺼져 있다"만 말한다. 깨우기가 생기면 꺼진 방 대부분은 "글을 쓰면 켜지는 방"이다. 왜 꺼졌는지(자동 내림·재부팅·`stop`)가 아니라 **지금 글을 쓰면 어떻게 되는지**로 나눈다 — 즉시 정확한 표시만 쓴다는 기존 결정과 같다.

| 구역 | 뜻 |
|---|---|
| 🔧 작업 중 · ⏳ 백그라운드 · 💤 대기 | 지금과 같다(켜져 있는 방) |
| 🌙 잠듦 N — `-# 글을 쓰면 깨어나` | 꺼져 있고 깨울 수 있는 방(깨우기 켜짐 + 폴더 있음) |
| ⚫ 꺼짐 N | 꺼져 있고 못 깨우는 방(깨우기 꺼짐 · 폴더 없음) |

- 내림·깨움 때 기존 신호(`dashboard_signal`)로 바로 다시 그린다.
- 로비는 지금처럼 #상태에 안 나온다.
- "세션이 꺼졌어(종료 코드 N)" 알림 끝에, 깨우기가 켜져 있으면 "여기에 글을 쓰면 다시 켜져"를 붙인다.

## 7. 설정

`~/.marina/discord.json` (비밀값 없음, 둘 다 없어도 된다):

```json
{
  "idleStopHours": 2,
  "wake": true
}
```

| 키 | 뜻 | 없을 때 |
|---|---|---|
| `idleStopHours` | 이만큼 쉬면 내린다. `0` = 안 내림. 2 미만은 2로 올린다(조건 A) | 기본값(§형 결정) |
| `wake` | `false` 면 깨우기(와 내리기)를 끈다 | 켜짐 |

환경변수(테스트·고정 경로용, 형이 쓸 일 없음): `MARINA_DISCORD_SUPERVISOR`(`launchd`·`nohup` 강제), `MARINA_DISCORD_LAUNCHCTL`(가짜 launchctl), `MARINA_LAUNCH_AGENTS_DIR`(plist 폴더).

## 9. 검증

### 단위 (격리: `lib/harness.sh` + `lib/session_fixture.sh`, 가짜 Discord·가짜 claude·전용 tmux 소켓)
- LaunchAgent: plist 내용(실행 인자·KeepAlive·AbandonProcessGroup·LANG), 주인 판정(격리 홈은 nohup), 없으면 bootstrap·있으면 kickstart·다르면 다시 올림, `off` 면 launchctl 호출 0건, **가짜 launchctl 만** 불렸고 실제 `~/Library/LaunchAgents` 는 안 건드림.
- 데몬: launchd 아래 핸드오프는 아무것도 안 띄움, 떼어 뜬 데몬은 등록 후 루프 없이 끝남, 동시 `ensure` 5개에 등록 1번.
- 깨우기: 켜진 방 무시, 허용 안 된 사람 무시, 봇 글 무시, 동시 2건에 기동 1번, 밀린 글 3개가 태그 3개로 한 지시에, 10분보다 오래된 글은 개수만, 8KB 넘으면 본문 빠짐, 스레드 글, 워크트리 없는 방 실패 안내 1번(10분 안 두 번째는 안내 없음), 첫 지시가 채팅 인자에서 `--settings` 뒤 마지막 원소, `RESUME_TEXT` 안 겹침, 깨운 뒤 확인(놓친 글 있으면 문구 1번·없으면 0번), 뜰 때 훑기(beat 없으면 0건·12시간 넘은 글 0건).
- 내리기: 조건 1~7 각각이 막는지, 60초 연속·직전 재확인, 한 바퀴 하나, 판정 예외면 안 내림, **자기가 만든 tmux 세션만**(전용 소켓) 죽임, 내린 뒤 밀린 글 있으면 다시 깨움.
- #상태: 꺼진 방이 🌙/⚫ 로 나뉨, 구성요소 40개 한도 유지.
- `test-py39-compat`·`test-discord-boundary` 통과.

### 실측 (형 맥·Discord 테스트 채널, 지휘 세션·qa — 배포는 형 허락 뒤)
1. `launchctl print gui/$(id -u)/marina.discord` 가 running. 데몬을 `kill -9` → 10초쯤 뒤 다시 뜨고 봇·#상태가 돌아온다. 데몬·bun 봇이 각각 하나(`pgrep` 으로 수 확인).

7. 깨운 개발 세션에서 `which node`·`echo $PATH` 가 손으로 켠 세션과 같다.

## 형 결정 (2026-10-07)

1. **내리는 기준 시간: 2시간.** `IDLE_DEFAULT_HOURS = 2`(= 하한과 같다. 캐시가 1시간이라 그 뒤로는 내려도 토큰 차이가 없다). `idleStopHours` 로 늘릴 수 있고 2 미만은 2로 올린다. §7 표의 "기본값"은 2시간.
