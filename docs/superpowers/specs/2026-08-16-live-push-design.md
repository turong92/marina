# 실시간 전달과 알림 설계 (2026-08-16)

## 왜

형이 폰으로 마리나를 쓰면서 두 가지를 지적했다.

1. **"폴링중인게 보이지도 않으니 멈춘 것 같고 엄청 느리잖아 체감이"** — 모바일은 3초마다 조용히
   상태를 물었다. 화면에 아무 표시도 남기지 않아 살아있는지 알 수 없었고, 무엇을 하든 최대
   3초가 밀렸다.
2. **"나 폰인데 너한테서 알림이 안오거든?"** — 모바일엔 알림 코드가 0줄이었다. 웹 대시보드엔
   있었지만 서비스 기동 완료/실패만 알렸다.

셋째 이유가 더 근본적이다. **마리나엔 "무엇이 바뀌었나"를 아는 곳이 없었다.** 화면이 물어보면
그때 계산할 뿐이라, 알림을 보낼 근거 자체가 없었다.

## 무엇을 만들었나

세 층으로 나눴다. 각 층은 아래층만 알고, 위층이 누구인지 모른다.

```
   변화 감지 (marina_events)
        │  사건: question · idle · blocked · service · message
        ├──────────────┬──────────────────┐
   판단 (marina_notify)                전달 A: SSE  ── 화면이 열려 있을 때
        │                                  /mobile/api/events
   전달 B: 웹 푸시 (marina_push)        ── 폰이 잠겨 있을 때
```

### 1. 변화 감지 — `marina_events.py`

**두 신호를 합친다.**

- **훅이 찌른다(지연 0)** — 형이 고른 네 순간 중 셋(질문·턴 종료·막힘)은 이미 훅이 잡고 있다.
  훅은 저널을 쓴 뒤 데몬에 `POST /api/events-poke` 한 줄을 보낸다. 훅은 턴을 붙잡고 도는
  코드라 **절대 기다리지 않고 실패해도 무시한다**(0.4초 타임아웃).
- **감시 루프(안전망, 0.3초)** — 훅이 없는 세션(밖에서 띄운 CLI), 서비스 상태, 훅이 유실된
  경우를 덮는다. 상태 계산이 1.7초 → 0.08초로 싸졌기에 가능해진 선택이다.

**파일 감시(fsevents)를 쓰지 않은 이유**: 외부 의존성이 필요하고(마리나는 표준 라이브러리
전용), 파일 교체·새 세션 등장에서 조용히 놓치는 실패가 생긴다 — 방금 캐시 작업에서 잡아낸
바로 그 부류다.

**사건의 구분이 곧 알림 정책이다.** `question`·`idle`·`blocked`·`service`는 사람을 불러야
하는 일, `message`는 화면만 따라가면 되는 일. 이 선을 여기서 한 번 그으면 아래 두 전달층이
같은 기준을 쓴다.

**첫 스냅샷은 기준선일 뿐 사건이 아니다.** 없으면 데몬이 뜨는 순간 살아있는 세션 수만큼
알림이 쏟아진다.

**계산은 프로세스당 한 번.** 폰이 몇 대 붙어도 감시 루프는 하나다. 폴링 대비 진짜 이득이
여기서 나온다.

### 2. 판단 — `marina_notify.py`

규칙 넷:

| 규칙 | 이유 |
|---|---|
| 네 종류만 알린다 | `message`로 울리면 글자마다 진동한다 |
| 지금 쓰는 세션만(12시간 내 활동) | 세션이 34개다. 어제 것까지 부르면 알림이 의미를 잃는다 |
| 같은 (세션, 종류)는 60초에 한 번 | 상태가 떨렸다고 두 번 울리지 않는다 |
| **보고 있는 대화는 안 울린다** | 서버는 누가 무엇을 보는지 모른다 → 서비스워커가 마지막에 거른다 |

**알림 본문에 대화 내용을 싣지 않는다.** 잠금화면에 남고, 열면 어차피 보인다. "물어볼 게
있어요 / 마리나 고치기" 정도만 준다.

### 3. 전달 A: SSE — `/mobile/api/events`

**폴링을 없애지 않았다.** 터널·프록시가 스트림을 접는 환경이 실제로 있어서(예전 미리보기
프록시에서 겪었다), 폴백을 없애면 그런 데서 화면이 통째로 멈춘다.

- 스트림이 붙어 있으면 폴링을 15초로 늦춘다(어긋남 보정용).
- 끊기면 3초로 되돌리고, 1→2→4…30초로 뜸해지며 재연결한다.
- 화면을 끄면 스트림을 접고, 돌아오면 즉시 붙는다.
- **연결 상태를 헤더의 점으로 보여준다** — 형이 "멈춘 것 같다"고 느낀 자리다.

**사건은 신호일 뿐, 화면의 진실은 여전히 `state`다.** 사건을 받으면 상태를 한 번 당겨온다.
사건 안의 값으로 화면을 직접 고치면 서버와 화면이 두 벌로 갈라진다.

### 4. 전달 B: 웹 푸시 — `marina_push.py` + `sw.js`

**의존성 0으로 만든 방법.** 웹 푸시로 *내용*을 보내려면 RFC 8291 암호화(ECDH + HKDF +
AES-128-GCM)가 필요한데 이 환경엔 암호 라이브러리가 하나도 없다. AES-GCM을 손으로 구현하는
것은 위험하고, 의존성을 들이면 배포 방식이 바뀐다.

그래서 **내용 없는 푸시**를 보낸다(RFC 8030이 허용). 폰이 깨면 서비스워커가 마리나에
`/mobile/api/alerts?since=…`로 물어 무엇을 띄울지 정한다. 필요한 암호는 VAPID 서명(ES256)
하나뿐이고 그건 이미 깔린 openssl로 한다.

**덤**: 알림 내용이 애플·구글 서버를 지나가지 않는다.

**키는 한 번만 만든다.** 바뀌는 순간 등록된 모든 구독이 죽는다(0600, `~/.marina/push-vapid.pem`).

**죽은 구독 정리**: 404/410은 확답이라 즉시 삭제, 그 외 실패는 5회까지 세다가 삭제.

## 아이폰 조건 (형이 알아야 할 것)

1. **홈 화면에 추가**해야 알림 권한이 생긴다. 사파리 탭에서는 원천적으로 불가능하다.
   그래서 매니페스트·아이콘·`apple-mobile-web-app-*` 메타를 넣었다.
2. **https 주소에서만** 구독이 된다. 집에서 `http://…:3900`으로 열면 안 된다 —
   폰에서는 Funnel 주소를 쓸 것.

둘 다 안 될 때 **이유를 그대로 말한다**("홈 화면에 추가한 뒤 거기서 열면 알림을 켤 수 있어요").
조용히 실패하면 형이 고칠 방법이 없다.

## 배포 전에 재서 잡은 것 두 가지

측정하지 않았으면 그대로 나갔을 문제들이다.

**① 감시 루프가 git 을 초당 40번 돌렸다.** 루프가 화면용 `mobile_state()` 를 그대로 썼는데
거기엔 워크트리 배지(브랜치·dirty·ahead)가 딸려 있다. 그 캐시는 15초 TTL 이라 0.3초 루프가
계속 만료를 건드려 백그라운드 갱신이 쉬지 않고 걸렸다 — 워크트리 28개 기준 **초당 git 40회**.
감지에 필요한 건 세션의 상태·질문·마지막 활동뿐이라 전용 경량 스냅샷(`mobile_watch_state`)을
따로 뒀다. **초당 40회 → 0.1회.**

**② 듣는 사람이 없어도 촘촘히 돌았다.** 0.3초 고정이면 아무도 안 보는 동안에도 코어의 2.7%를
계속 먹는다. SSE 연결도 등록된 폰도 없으면 15초로 늦춘다(훅이 찌르면 어차피 즉시 깬다).
**유휴 2.7% → 0.66%**, 폰이 붙으면 다시 0.3초.

## 곁가지로 고친 것: "오랜만에 들어가면 첫 화면이 느리다"

형이 물어서 파보니 이 작업과 **별개 원인**이었다. 워크트리 배지 캐시는 2분(`MAX_STALE`)이
지나면 옛 값을 버리고 **동기로** 다시 계산한다. 2분만 안 들어가도 모든 워크트리가 그 선을
넘어서, 다음 요청 하나가 root 28개 × git ~24회를 통째로 기다린다.

순서를 뒤집었다: **먼저 옛 배지로 그리고 뒤에서 갱신.** 브랜치 이름이 몇 분 낡아도 해가 없고
만료 즉시 백그라운드 갱신이 걸려 곧 최신이 된다. 동기 계산은 캐시가 아예 없을 때(첫 방문·
데몬 재시작)만 남겼다. **실측 9.0초 → 2.3초.**

## 남은 것

- 웹 대시보드도 같은 SSE를 쓸 수 있다(지금은 모바일만). 배관은 공유되니 붙이기만 하면 된다.
- 세션별 알림 끄기(현재는 전체 on/off + 숨긴 세션 제외).
- 실제 아이폰에서의 설치·구독·수신 확인은 형의 폰에서만 가능하다.
