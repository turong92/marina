# 세션 패널 스캔성 개편 — 밀도 · 정렬 · 핀 · 워크트리 생성

날짜: 2026-07-31
상태: 설계 승인 대기

## 문제

형의 말: "좌측 카드패널에 텍스트가 너무 많아서 한 번에 눈에 안 들어오고. 조절이나 즐겨찾기 등
없어서 다시 찾아가기 힘들거든? 작업 완료 최신순도 아니고 정렬이. 내가 수정 할 수 있는거도 아니고."

찾는 대상은 **세션**이고, 그걸 **워크트리 찾기가 감싸고 있다**(중첩). 두 층 다 스캔이 안 된다.

### 코드에서 확인한 사실

1. **서버 정렬은 맞다.** `mobile_state` 가 `sessions.sort(key=ts, reverse=True)` 로 내려준다.
   `ts` = 트랜스크립트 파일 mtime = 마지막 활동. 워크트리 그룹 순서도 "그 안 최신 세션" 기준으로 나온다.

2. **화면에서 순서가 얼어붙는다 — 이게 "최신순이 아니다"의 실체.**
   `renderSessions` 의 구조키가
   ```js
   sessions.map(s => `${source}:${key}:${status}`).sort().join("|")
   ```
   로 `.sort()` 를 걸어 **순서에 둔감**하다. 세션 집합과 상태 문자열이 그대로면 구조키가 같고, 그때는
   카드 **텍스트만** 갈아끼우고 위치는 건드리지 않는다(patch-only 경로). 결과: 어떤 세션에서 일해
   mtime 이 올라가도 위로 올라오지 않는다. 재정렬은 세션이 추가/삭제되거나 상태가 바뀔 때만 일어난다.

3. **밀도.** 카드 한 장 = 제목 + 부제(경로 + 모델·에포트) + 미리보기 3줄 + 배지들, `min-height: 88px`.
   워크트리 그룹은 전부 `<details open>` 이라 항상 펼쳐져 있다.

4. **조절 수단 0.** 정렬·밀도·즐겨찾기 어느 것도 모바일·웹 양쪽에 없다.

5. **세션은 7일이면 사라진다** (`AGENTS_MAX_AGE = 7 * 86400`). 워크트리는 등록된 채 남는다.
   → 수동 배치(자리바꿈)를 **세션**에 붙이면 대상이 증발해 순서가 저절로 무너진다.

6. **모바일엔 워크트리 생성이 없다.** `/api/worktree-create` 는 웹 전용이고, 모바일엔 UI 도 경로도 없다.
   그리고 `/api/*` POST 는 **호스트 가드**가 걸려 있어(`do_POST` 의 `host_guarded`) 펀넬 호스트에서
   직접 부르면 `forbidden host` 다. `/api/mobile-send` 만 예외로 빠져 있다 — 모바일 표면은 의도적으로
   `/mobile/api/*` 에 산다.

## 원리 (모바일·웹 공통)

동작 원리는 양쪽이 같다. **값**까지 같을 필요는 없다(아래 저장 위치 참고).

1. **정렬은 단일 규칙**: 핀 먼저 → 그 외 마지막 활동 최신순. 정렬 선택 UI 는 두지 않는다.
2. **밀도 2단계**: 간단(기본) ↔ 자세히.
3. **워크트리 그룹은 기본 접힘.** 예외로 자동 펼침: 지금 보고 있는 세션이 있는 그룹, 질문대기/작업중이
   있는 그룹.
4. **수동 배치는 오래 사는 것에만.** 핀은 **워크트리**에 붙인다(세션은 7일이면 증발).

## 설계

### 1. 세션 한 줄 (간단 모드)

```
[CC] 큐 문신·정렬 정합성 고치기            ● 12분
[CX] 게이트웨이 만료 토큰 조사             ◌ 어제
[CC] compose watch 플레이키                ? 질문대기
```

- 남긴다: 출처 배지 · 제목(말줄임) · 상태점 · 마지막 활동 상대시간
- 뺀다: 부제(경로 + 모델·에포트), 미리보기 → **자세히** 모드에서만
- 질문대기는 색만으론 약하므로 `?` 기호까지 붙인다(놓치면 안 되는 유일한 신호)
- 제목 우선순위: 별칭 > AI 타이틀 > head subject (별칭은 이미 존재하는 식별 수단)

### 2. 워크트리 그룹 한 줄

```
📌 ● asdf                     3  ＋CC ＋CX
▸  ◌ mdc-main                 1  ＋CC ＋CX
```

- 별칭 우선, 없으면 디렉터리명
- **접힌 상태에서도** 그 안 "질문대기 / 작업중" 개수를 배지로 노출한다. 안 그러면 접기가 정보를 숨긴다.

### 3. 정렬 결함 수정

- 구조키에서 `.sort()` 를 제거해 **순서를 키에 포함**시킨다.
- 순서가 바뀌면 DOM 을 재배치하되 **노드를 재사용**한다(`insertBefore`). 새로 만들면 폴링마다
  스크롤·펼침·포커스가 튄다. 웹에 이미 keyed reconciler 가 있다(`app-0b-reconcile.js`) — 모바일도
  같은 방식으로 맞춘다.

### 4. 핀 (즐겨찾기)

- 대상: **워크트리**. 핀한 것은 목록 맨 위 고정, 그 안에서는 최근활동순.
- 조작: 그룹 헤더 길게 누르기 또는 헤더의 핀 아이콘.
- **저장: 서버**(`MARINA_HOME`). 폰에서 꽂은 핀이 웹에도 보여야 "다시 찾아가기"가 성립한다.
  - `GET/POST /mobile/api/pins` (모바일 토큰 허용) + 웹은 같은 저장소를 읽는다.
- 자리바꿈(드래그)은 **넣지 않는다**. 근거: 세션은 7일이면 사라져 수동 순서가 무너지고, 폰에서 드래그는
  드로어 엣지 스와이프와 제스처가 충돌하며, 이득이 핀과 거의 겹친다. 필요해지면 2단계로 **핀 목록
  내부에서만** 순서 변경을 검토한다.

### 5. 모바일 워크트리 생성

- **새 경로 `/mobile/api/worktree-create`** 를 낸다. `/api/worktree-create` 를 그대로 쓰면 호스트
  가드에 막힌다(사실 6). 다른 모바일 기능과 같은 규약: 모바일 토큰 또는 principal, 프로젝트 접근 검사.
- 서버 로직은 기존 것을 재사용한다: 등록된 프로젝트 root + 브랜치명 → `marina worktree create <branch>`.
- 진입점: 프로젝트 그룹 최상단의 `＋ 워크트리`. **워크트리 그룹 헤더가 아니다** — 기존 `＋CC/＋CX` 와
  헷갈리지 않게 층을 분리한다.
- 라벨 정리: `＋CC/＋CX` 는 "그 워크트리 안에 **세션**을 하나 더"라는 뜻이 드러나게 툴팁/aria 를 손본다.
  (형이 `+` 를 "워크트리 만들기"로 읽은 것이 이번 혼선의 원인.)
- **오래 걸린다**: 서브레포 attach 때문에 최대 180s. 버튼을 얼려두지 않고 진행 상태를 보여주고,
  실패 사유를 그대로 노출한다(현재 웹은 타임아웃 문구를 준다).

### 6. 조절 UI

패널 상단(검색창 줄)에 **밀도 토글 하나**. 정렬 선택은 두지 않는다 — 규칙 하나가 맞게 도는 것이
선택지를 주는 것보다 낫고, 형의 원 불만("최신순이 아닌데 고칠 수도 없다")은 규칙 수정 + 핀으로 해소된다.

- **밀도 저장: 기기별(localStorage).** 밀도는 화면 크기에 따라 다른 것이 자연스럽다(폰=간단,
  데스크톱=자세히). 강제로 묶으면 한쪽이 계속 불편하다.
- **핀 저장: 서버.** (위 4번)

## 비목표 (YAGNI)

- 정렬 선택 UI
- 세션 단위 핀
- 드래그 자리바꿈
- 밀도 3단계 이상

## 범위와 순서

1. 모바일: 정렬 결함 수정 → 밀도/접힘 → 핀(서버) → 워크트리 생성
2. 웹: 같은 규칙 적용(핀 저장소 공유, 접힘 기본, 한 줄 밀도). 웹은 이미 reconciler 가 있으므로
   순서 결함이 있는지 먼저 확인한다.

## 테스트

- **정렬**: `ts` 만 바뀌었을 때 구조키가 달라지고 DOM 순서가 실제로 재배치되는지. 노드가 재사용되는지
  (교체가 아니라 이동인지) — 스크롤/펼침 보존의 근거.
- **밀도**: 간단 모드에 부제/미리보기가 없고, 자세히 모드에 있는지. 토글이 저장되는지.
- **접힘**: 기본 접힘이고, 현재 세션·질문대기·작업중 그룹은 펼쳐지는지. 접힌 헤더에 개수 배지가 있는지.
- **핀**: 핀한 워크트리가 최상단이고 그 안은 최근순인지. 서버 왕복 후에도 유지되는지.
- **워크트리 생성**: `/mobile/api/worktree-create` 가 모바일 토큰으로 되는지, 호스트 가드에 안 걸리는지,
  등록 안 된 root/이상한 브랜치명을 거부하는지, 오래 걸릴 때 UI 가 얼지 않는지.
