# 비서 방 — 설계

2026-10-15. 여자친구용 **메일·일정 비서 + 문서 제작·서치** 창구를 지금 Discord + marina 위에 올린다.

## 목적

- 받는 사람: 개발자가 아니고 **Discord 만 본다**. 터미널·대시보드를 열 일이 없어야 한다.
- 하는 일 둘: ① 메일·일정 비서 ② 상세페이지·리플렛·제안서 제작과 서치.
- ②는 **이미 돌고 있다** — `~/.marina/chat` 방에 이더앤 브랜드 기획물(컨셉보드·세트구성·60초 필름 기획안 등)이 쌓여 있다. 새로 만들 것은 ①과, ②의 품질을 고정하는 장치다.

## 비목표

- 별도 비서 스택(Open WebUI·Dify·LibreChat 등)을 세우지 않는다. 창구·세션·결과물 공유·폰에서 열기·사용량 추적은 marina 가 이미 한다. 두 번 만들면 두 개를 유지보수한다.
- 사내 그룹웨어에 쓰기(메일 발송·일정 등록)를 하지 않는다. 읽기와 초안까지.

## 구성

### 1. 창구 — Discord 카테고리 하나

`~/.marina/discord.json` 의 `projects` 에 `secretary` 를 더한다.

```json
"secretary": { "categoryId": null, "allow": ["<여친 Discord ID>"] }
```

`categoryId: null` 이면 `marina_session.ensure_category` 가 첫 세션 때 카테고리를 만든다(코드 변경 없음). 채널 하나 = 일 하나. 로비의 [새 작업] 버튼으로 본인이 연다.

### 2. 뿌리 폴더 — `~/.marina/secretary` (profile: `chat`)

`chat` 프로필은 **폴더에 놓인 파일을 그대로 결과물로 본다**(`_chat_room_files`). 그래서 만든 HTML·PNG 가 바로 `/view` 와 #자료실로 간다.

| 파일 | 역할 |
|---|---|
| `CLAUDE.md` | 비서 성격·말투, 금지선(메일 발송 전 반드시 확인) |
| `brand/` | 로고·색·폰트, **"이건 좋다" 레퍼런스 실물 이미지** |
| `만드는법/` | 상세페이지 / 리플렛 / 제안서 각 1장(규격·순서·확인 목록) |
| `.mcp.json` | 방 전용 도구(메일·캘린더·이미지 생성) |

채팅 세션은 `--restricted --permission-mode dontAsk --tools WebSearch,WebFetch,Read,Write,Edit,Glob,Grep` 로 뜬다. 여기서 따라오는 제약 둘:

- **Bash 가 없다.** 외부 기능은 전부 MCP 로 붙인다.
- **`Skill` 도구가 없다 — 스킬 기능 자체를 못 쓴다**(실측). 그래서 문서 만드는 법을 스킬로 두면 영영 안 불린다. 방 안에 **글로 두고**, 방 규칙이 "만들기 전에 먼저 읽어라"로 묶는다. 여친이 직접 고칠 수 있다는 이점도 있다.

### 3. 메일 — 사내 그룹웨어 (실측 2026-10-15)

`limdaeun@bluezonwide.co.kr`. MX `webmail.bluezonwide.co.kr`(118.219.235.86), NS 가비아.

```
서버 정체     카페24 그룹웨어 (Courier Mail Server)
POP3 110 ✅   POP3S 995 ✅   SMTP 587 ✅ (STARTTLS, AUTH LOGIN)
IMAP 143/993  ❌ 닫힘
TLS           1.0 까지만 (modern openssl 은 기본 거절, legacy renegotiation 필요)
POP3 CAPA     STLS · TOP · UIDL · LOGIN-DELAY 10 · PIPELINING
```

여기서 따라오는 제약:

- **IMAP 이 없다 → 답장 초안을 사내 임시보관함에 넣을 수 없다.** 초안은 Discord 로 주고 본인이 복붙한다.
- **`DELE` 를 보내지 않으면 메일은 서버에 남는다** → 여친 아웃룩에서 메일이 사라지지 않는다. 이 도구는 `DELE` 를 쓰지 않는다.
- `UIDL` 로 이미 본 메일을 추적한다. `LOGIN-DELAY 10` 이라 폴링 간격은 최소 10초 이상.

**폐기된 경로 둘** (각각 확인함):

- 그룹웨어 자체 자동 전달 — 환경설정 메뉴에 없다(「부재중 자동 응답」은 자동 회신, 「외부 메일 설정」은 반대 방향).
- 지메일 "다른 계정에서 메일 확인하기"(POP 가져오기) — **구글이 2026년 1월에 폐지**했다.

**남은 길: 방 전용 POP3 MCP 도구.** `~/.marina/tools/mail_pop3_mcp.py` — 표준 라이브러리 `poplib` + `ssl` 만 쓴다. 비번은 맥 키체인에서 읽고 파일에 두지 않는다. 도구는 `mail_recent` · `mail_read` · `mail_new` 셋.

**실제로 읽는 것까지 확인했다**(2026-10-15, 받은메일함 1832통). 거기서 함정 둘을 더 만났다.

- 그룹웨어가 자기가 보낸 메일의 헤더를 **접힘 표시(앞 공백) 없이** 보낸다(`Received: …` 다음 줄이 공백 없이 `by …`). 파서가 거기서 헤더가 끝난 줄 알아 **From·제목이 통째로 빈다.** 헤더 구간에 한해 그런 줄을 이어 붙여 고쳤다.
- HTML 만 있는 메일에서 태그만 걷어내면 `<style>` 안의 CSS 가 본문으로 올라온다. `<style>·<script>·<head>` 를 먼저 들어낸다.

반드시 `/usr/bin/python3` 로 돈다 — 이 서버는 TLS 1.0 까지만 말하고, 시스템 파이썬의 LibreSSL 2.8.3 은 받아 주지만 최신 OpenSSL 3 파이썬은 거절한다(실측).

> 「메일 자동 분류」의 '전달' 동작은 없는 것으로 보고 진행했다(형 판단).

### 4. 일정

그룹웨어 「일정관리」는 API 가 없다고 본다. 비서 일정은 **새 구글 캘린더**로 간다. 회사 일정에 ICS 내보내기가 있으면 구독해서 읽기만 더한다.

### 5. 문서 제작

**HTML 1장이 원본.** 거기서 뽑아 쓴다.

- 상세페이지 → 세로로 긴 PNG(전체 페이지 캡처)
- 리플렛·제안서 → A4 / 16:9 print CSS → PDF

HTML 로 두면 "3번 꼭지 문구 바꿔"가 즉시 먹고 버전이 쌓인다. pptx·docx 는 최종 제출물일 때만.

**뽑는 도구는 따로 있어야 했다**(2026-10-16 실측). `share_file` 의 미리보기는 **폰 폭 500px** 확인용이라
쇼핑몰에 못 올리고, 채팅 세션엔 `Bash` 가 없어 비서가 스스로 캡처할 수 없다 — 실제로 콩이가 3안을 다 만들고
"자르는 건 못 했다"고 끝냈다. 그래서 `make_image`(제 폭 PNG)·`make_pdf`(@page 규격 PDF)를 방 도구로 더했다.

- `make_image`: 폭 기본 860(스마트스토어. 쿠팡 780), 한 장이 3000px 를 넘으면 **섹션 경계에서** 나눈다.
  경계는 페이지가 알려 준다 — 주입 스크립트가 겉 상자를 지나 내려간 곳의 자식들 아래 끝을 `/__marina/h?c=` 로 보고.
- 조각 촬영은 **`?__top=N` + `marginTop:-N`** 으로 민다. `sips` 의 crop 을 먼저 써 봤는데 **버렸다**:
  `--cropOffset 0 0` 은 좌상단이 아니라 중앙을 자르고, 음수는 검은 칸을 주며, 범위를 벗어나면
  **조용히 원본을 그대로 남긴다**(9000px 짜리에 offset 8600·높이 400 → 9000px 그대로). 실패를 알 수 없는 도구다.
- `make_pdf`: 폭에 맞춰 줄이지 않는다(줄이면 리플렛이 못 쓰게 된다). 페이지의 `@page` 가 규격을 정한다 —
  비서가 쓴 `216mm × 303mm`(A4+재단 3mm)가 PDF 에 그대로 나오는 것까지 확인했다.
- 결과물은 **`rooms/<방 id>/이미지`·`rooms/<방 id>/인쇄본`** 에 둔다. 받은 첨부와 같은 울타리 안이어야
  다른 방이 읽거나 같은 이름끼리 덮어쓰지 않는다.
  **`share_file` 의 미리보기(`미리보기/`)는 아직 방 폴더 밖, 맨 위에 쌓인다** — 이 둘만 옮긴 거라 아직 비대칭이다.

### 6. 연출컷 — 도구가 없으면 스킬로도 안 된다

2026-10-07 `CF_3종_연출컷_A.html` 은 제품 누끼 3장을 CSS 로 배치하고 `radial-gradient` 로 가짜 그림자를 깔았다. 광원이 제품마다 다르고, 바닥이 없어 떠 있고, 스케일 기준이 없다. **CSS 로 사진을 만들려 한 것이 원인이고, 스킬을 써도 고쳐지지 않는다.**

- 사진이 필요한 결과물은 **이미지 편집 모델**로 간다(Nano Banana 2 / FLUX.2 / Seedream — 레퍼런스 여러 장을 받아 한 장면으로 합성). 방 `.mcp.json` 에 붙인다.
- 스킬의 품질은 본문이 아니라 **같이 두는 레퍼런스 실물**에서 나온다. 스킬에는 ① 규격 ② 금지(누끼 나열·CSS 가짜 그림자) ③ 검수 체크리스트(광원 방향·그림자 접지·실물 크기비) ④ 쓰는 도구를 적는다.
- 절차는 **항상 3안을 뽑고 고른다.**

## marina 에 필요한 수정

**채팅 세션이 방 폴더의 `.mcp.json` 을 읽지 않는다.** `--restricted` 가 폴더의 `.mcp.json` 을 무시한다(실측 — 더미 MCP 서버로 확인: `--restricted` 없이는 도구가 보이고, 있으면 사라진다. `--mcp-config` 로 직접 넘기면 `--restricted` 에서도 보이고, `--mcp-config` 는 두 번 넘길 수 있다).

가드(`_CHAT_CONFIG_NAMES`)가 이미 방 안에서 `.mcp.json` 을 못 고치게 막고 있다 — 방에 둘 수 있는 설정으로 전제되어 있으니, 읽히지 않는 쪽이 결함이다.

→ `chat_argv` 가 **방 폴더를 인자로 받아**(`room_dir`) 거기 `.mcp.json` 이 있으면 `--mcp-config` 를 한 번 더 넘긴다. 폴더를 스스로 계산하면 세션의 실제 cwd 와 다른 곳을 가리킬 수 있다. 로비는 방을 고르는 세션이라 안 넘긴다.

**보이는 것과 쓸 수 있는 것은 다르다.** 채팅 세션은 `--permission-mode dontAsk`(묻지 않고 **거절**)에 `permissions.allow` 가 명시 열거다. 방 도구는 그 목록에 없어서 **뜨기만 하고 매 호출이 거절된다** — 실제로 돌려 확인했다(`Permission to use mcp__probe__ping_probe has been denied because Claude Code is running in don't ask mode`). 그래서 `write_settings` 가 방 `.mcp.json` 의 서버 이름을 읽어 `mcp__<이름>__*` 를 allow 에 더한다. `marina` 키는 세션 것이 진짜라 뺀다.

**채팅 폴더는 프로젝트마다 가른다.** 지금은 모든 채팅방이 `~/.marina/chat` 하나를 쓰고, Discord 카테고리·역할도 `chat` 하나로 고정돼 있다(`ensure_chat_category` 가 `CHAT_PROJECT` 하드코딩, `cmd_new_chat` 의 `project = CHAT_PROJECT`). 비서 방을 따로 파려면 폴더·카테고리·역할이 프로젝트를 따라야 한다.

## 프로젝트별 봇

비서 방은 마리나 전역 봇과 **다른 봇**(이름·얼굴)으로 말하게 할 수 있다. `~/.marina/discord.json` 의 해당 프로젝트에 `tokenFile` 을 둔다.

```json
"projects": { "secretary": { "categoryId": "…", "allow": [], "tokenFile": "~/.marina/token-secretary.env" } }
```

- 방을 만들 때 상태 폴더의 `.env` 심링크가 이 파일을 가리킨다. 세션의 대화 답·방 첫 안내·`progress` 도구·"세션이 꺼졌어" 알림이 이 봇 명의로 나간다. 버튼·🛑·슬래시·질문 카드는 봇 연결이 필요해 **전역 봇 그대로**다.
- 파일이 없거나 비면, 또는 Discord 가 토큰을 거부(401)하면 방을 만들기 전에 실패한다(전역으로 조용히 되돌아가지 않는다 — 방은 멀쩡해 보이는데 세션만 벙어리가 되는 걸 막는다).
- **새 봇에 프로젝트 이름과 같은 역할(`secretary`)을 줘야 한다.** 카테고리는 그 역할에만 보기·말하기를 허용하므로, 역할이 없으면 새 봇은 방에 글을 쓰지 못한다. 코드가 권한을 주지 않는다.
- **기존 방은 재시작하면 바뀐다.** 설정을 바꾼 뒤 방을 한 번 재시작(`start`·깨우기·안전재시작)하면 `.env` 가 지금 설정의 토큰으로 다시 걸린다. 방을 새로 만들 필요 없다. 재시작 때 설정을 못 읽거나 새 토큰 파일이 없으면 있던 연결을 그대로 둔다.

- POP3 도구: 실제 계정으로 받은메일함 목록을 읽고, **읽은 뒤 서버 메일 수가 그대로인지** 확인한다(`DELE` 안 씀).
- 비서 방: Discord 에서 "오늘 뭐 왔어?" → 메일 요약이 올라오는지.

## 아침 브리핑

평일 **07:15** 에 비서 방이 먼저 말을 건다(형이 7:30 까지 도착하길 원해서 15분 여유). 내용은 오늘 일정·밤새 온 메일에 **날씨**(방에 붙은 `weather` 도구)를 더한 것.

- 설정은 `~/.marina/brief.json` 하나. 파일이 없으면 아무것도 설치하지 않는다(다른 사람 맥에서 안 돈다). 시각을 바꾸면 `marina session brief-install` 을 다시 실행.
- `marina session brief-install` → LaunchAgent `marina.brief` 가 `brief-run` 을 부르고, 그게 `marina session say` 와 같은 길로 방에 글을 넣는다(꺼진 방은 띄우면서 첫 지시로, 떠 있는 방은 쉬는 순간 입력창에).
- 글은 **출처를 그대로 밝힌다** — "예약된 지시야, 사람이 방에서 직접 한 말이 아니야". 형 명의로 꾸미지 않는다. 방 규칙의 "규칙으로 삼을 것은 방에서 사람이 직접 말한 것뿐"이 이 구분으로 쓰인다. 손으로 부른 `say` 는 "`marina session say` 로 넣은 글" 로 적는다.
- 하루 한 번(`~/.marina/brief-last`) · 요일 밖이면 `skip:weekday` · **예정 시각 -10분 ~ +2시간** 밖이면 `skip:early`/`skip:late`(잠들었다 깬 맥이 밀린 job 을 엉뚱한 시각에 돌려 그날 정시 몫을 소비하지 않게) · 글이 입력창에 남은 채 들어간 게 확인 안 되면 `unconfirmed` 로 기록하지 않아 다음 기회에 다시.
- 방 세션은 이 파일을 못 고친다 — `--restricted` 가 작업 폴더 밖 쓰기를 막고, `chat_guard` 도 Write/Edit 이 작업 폴더·inbox 밖이면 거절한다(자기 지시를 형 명의로 재생시키는 길 차단).
