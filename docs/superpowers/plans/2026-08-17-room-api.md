# Room API 구현 계획 (1차)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 마리나가 "방(Room)"을 서버에서 먼저 계산하고, 지금의 모바일 세션 목록이 그 방 목록에서 **파생**되게 만든다.

**Architecture:** `marina_rooms.py` 를 새로 두고 방 조립을 한 곳에 모은다. 방은 워크트리 하나이고 그 안의 세션들이 탭이다. 상태는 **새 어휘를 만들지 않고** 지금 캐논 6개(`resolve_session_liveness`)를 5개로 **접기만** 한다. 화면은 이번 범위가 아니다 — `mobile_state` 의 응답 스키마를 그대로 유지한 채 계산 경로만 뒤집으므로, 기존 모바일 테스트가 그대로 안전망이 된다.

**Tech Stack:** Python 3.9 표준 라이브러리만(마리나 규칙 — 외부 의존성 금지), bash + inline python 테스트(`plugin/tests/lib/harness.sh` 필수).

**Spec:** `docs/superpowers/specs/2026-08-11-nondev-room-redesign-design.md`

## Global Constraints

- **표준 라이브러리만.** 새 pip 의존성 금지(스펙 §4 근거와 동일한 이유 — 배포 방식이 바뀐다).
- **git 을 부르지 않는다** — 방 목록 경로에서. 워크트리 배지는 '깃' 탭이 따로 가져간다(`worktree_labels` 가 그 규칙의 선례). 유일한 예외는 Task 2 의 변경 여부 판정이고, 그것도 캐시 뒤에 둔다.
- **상태 어휘는 6개 그대로 두고 표시층에서만 접는다**(스펙 §5). `resolve_session_liveness` 가 단일 캐논이다 — 새 상태를 만들지 않는다.
- **테스트는 `. lib/harness.sh` 로 실 `~/.marina` 를 격리**한다(테스트가 형의 진짜 상태를 읽거나 쓰면 안 된다).
- 주석·커밋 메시지는 **한국어**, 사용자는 "형". **왜 그렇게 했는지**를 적는다.
- 파일 하나가 커지면 쪼갠다 — `marina_mobile.py` 는 이미 크므로 **방 조립 코드를 거기 넣지 않는다**.

```python
"""방(Room) — 마리나가 사람에게 보여주는 일감 단위.

방 하나 = 워크트리 하나이고, 그 안의 세션들이 탭이다(스펙 §2). 이 파일은 **화면도 HTTP 도
모른다** — 조립만 한다. 그래야 모바일·웹이 같은 것을 보고, 계산이 두 벌로 갈라지지 않는다.

상태는 **새로 만들지 않는다.** `marina_sessions.resolve_session_liveness` 가 단일 캐논이고
여기서는 그 6개를 5개로 접기만 한다(스펙 §5).
"""
from __future__ import annotations

# 심각한 것부터. 방 안 탭들의 상태를 하나로 접을 때, 사람 조치가 필요한 것이 위로 올라와야
# 방 목록에서 놓치지 않는다(스펙 §2).
ROOM_STATUS_ORDER = ("문제", "응답필요", "작업중", "완료", "대기")

_STATUS_MAP = {
    "working": "작업중",
    "idle": "대기",
    "failed": "문제",
    "blocked": "응답필요",
    # waiting 은 코드 주석상 blocked 보다 순하지만(턴을 끝내고 프롬프트 대기), 사람에게
    # 요구하는 행동은 같다 — 뭔가 쳐야 움직인다. 색으로만 구분한다(스펙 §5).
    "waiting": "응답필요",
}


def room_status(status: str, has_changes: bool) -> str:
    """캐논 상태 하나를 방 상태로 접는다.

    completed 만 두 갈래다: 바뀐 파일이 있으면 완료, 없으면 대기(스펙 §4). completed 를
    그대로 완료로 보면 질문만 하고 끝난 턴·"못 합니다"로 끝난 턴까지 "일 끝났어요"가 되어
    카드 자체를 안 믿게 된다.

    모르는 값은 대기다 — CLI 가 새 어휘를 내놔도 화면이 깨지지 않아야 한다."""
    text = str(status or "")
    if text == "completed":
        return "완료" if has_changes else "대기"
    return _STATUS_MAP.get(text, "대기")
```

```python
# 방 목록 경로에서 git 을 부르는 **유일한** 자리다. 그래서 캐시 뒤에 둔다 — 방 목록은 폴마다
# 도는데 워크트리마다 git 을 돌리면 오늘 잡은 "초당 git 40회"가 그대로 재현된다.
_CHANGES_TTL_S = 20.0
_changes_cache: dict[str, tuple[float, bool]] = {}


def _git(args: list[str], cwd: Path) -> str:
    out = subprocess.run(["git", "-C", str(cwd), *args],
                         capture_output=True, text=True, timeout=5)
    return out.stdout


def room_has_changes(root: Path, *, runner: Callable[[list[str], Path], str] | None = None,
                     now: float | None = None) -> bool:
    """이 워크트리에 **볼 만한 결과**가 있나 — 완료 판정의 재료(스펙 §4).

    미커밋 변경과 base 보다 앞선 커밋을 **둘 다** 본다. 커밋까지 끝낸 경우를 빼먹으면
    "다 해놓고 커밋했더니 완료가 아니라고 나오는" 일이 생긴다.

    실패하면 False 다 — git 이 없거나 깨진 워크트리 하나 때문에 방 목록 전체가 죽으면 안 된다."""
    key = str(root)
    current = time.time() if now is None else now
    cached = _changes_cache.get(key)
    if cached is not None and current - cached[0] < _CHANGES_TTL_S:
        return cached[1]
    run = runner or _git
    try:
        dirty = bool(run(["status", "--porcelain"], root).strip())
        ahead = bool(run(["log", "--oneline", "@{upstream}..HEAD"], root).strip()) if not dirty else True
    except Exception:
        return False        # 캐시에 넣지 않는다 — 다음 기회에 다시 본다
    result = bool(dirty or ahead)
    _changes_cache[key] = (current, result)
    return result
```

```python
def fold_status(tab_statuses: list[str]) -> str:
    """탭들의 상태를 방 상태 하나로. 사람 조치가 필요한 것이 위로 올라온다(스펙 §2).

    방 목록에서 놓치면 안 되는 순서라, '가장 최근'이 아니라 '가장 급한' 것을 고른다."""
    for candidate in ROOM_STATUS_ORDER:
        if candidate in tab_statuses:
            return candidate
    return "대기"


def build_room(root: Path, labels: dict[str, Any], agents: list[dict[str, Any]], *,
               has_changes: bool, questions: Callable[[str, str], Any]) -> dict[str, Any]:
    """방 하나를 조립한다 — 워크트리 1개 + 그 안의 세션들(탭).

    이름은 **하나**다. 배경에 적힌 "이름이 세 번 반복된다"가 여기서 다시 나오지 않도록,
    별칭 → 세션 제목 → 워크트리 id 순으로 **한 줄만** 고른다. 슬러그는 상세에서만 쓴다.

    questions 는 "이 세션이 답을 기다리는 질문이 있나"를 돌려주는 함수다. 있으면 그 탭은
    실행 중이 아니라 **형 차례**이므로 응답필요로 본다."""
    tabs: list[dict[str, Any]] = []
    for agent in sorted(agents, key=lambda a: float(a.get("ts") or 0), reverse=True):
        source, sid = str(agent.get("source") or ""), str(agent.get("sid") or "")
        pending = questions(source, sid)
        canon = "blocked" if pending else str(agent.get("status") or "idle")
        tabs.append({
            "source": source,
            "sid": sid,
            "title": str(agent.get("title") or sid or source),
            "status": room_status(canon, has_changes),
            "primary": not tabs,          # 마지막 활동이 가장 최근인 탭 — 방을 열면 이게 먼저
        })
    name = (str(labels.get("alias") or "").strip()
            or str(labels.get("sessionTitle") or "").strip()
            or str(labels.get("id") or "").strip())
    return {
        "id": str(labels.get("id") or ""),
        "name": name,
        "project": str(labels.get("projectLabel") or ""),
        "projectId": str(labels.get("projectId") or ""),
        "root": str(root),
        "status": fold_status([tab["status"] for tab in tabs]),
        "tabs": tabs,
        "lastAt": max((float(a.get("ts") or 0) for a in agents), default=0),
        # 배포는 지금 만들지 않는다 — 자리만 잡아둔다(스펙 §확장 지점).
        "canShip": False,
    }
```

```python
def rooms_payload(roots: list[Path], *, labels: Callable[[Path], dict[str, Any]],
                  agents: Callable[[Path], list[dict[str, Any]]],
                  questions: Callable[[str, str], Any],
                  has_changes: Callable[[Path], bool]) -> list[dict[str, Any]]:
    """워크트리 목록을 방 목록으로. 호출자가 자료를 주입한다 — 이 파일은 마리나의 다른 층을
    import 하지 않는다(그래야 순수하게 테스트된다)."""

    for root in roots:
        try:
            rooms.append(build_room(root, labels(root), agents(root),
                                    has_changes=has_changes(root), questions=questions))
        except Exception:
            continue        # 워크트리 하나가 깨져도 나머지 방은 보여야 한다
    return rooms
```

- **삭제(대화 탭·방) + 미커밋 자동 보관** — 되돌릴 수 없는 동작이라 방 모델이 자리 잡은 뒤에 따로 계획을 끊는다. 묘비 저장(마리나는 세션을 파일 스캔으로 발견한다)과 `wip/` 보관 커밋이 함께 필요해 분량도 별개다.
- **화면(멤버 모바일·어드민 웹 서랍)** — 스펙 §다음 단계가 "API 가 흔들리면 화면 두 벌을 같이 고쳐야 한다"고 적어둔 그대로다. 이 계획이 끝나야 화면을 그 위에 올린다.
- **미리보기 절대경로 잔여 항목** — 앱을 띄워봐야 드러나는 종류라 계획으로 못 묶는다.
